# Source Digests

Use this file as a provenance and intake map. It summarizes useful content already absorbed into this skill so future users do not need the original links or local files merely to design a general.

## Online Design Essays

- https://www.bilibili.com/opus/1107326926420181009, "风雨如晦（上）": large historical-card design set. Useful lessons: choose concrete historical anchors, let a rule describe a sequence instead of one static trait, and treat non-三国杀 card-game mechanics only as inspiration after translation.
- https://www.bilibili.com/opus/825088145580097537, "曹宪曹华等上半年设计汇总": major source for design发端, internal linkage, locked-skill categories, and naming/title practice. Key lesson: decide the creative origin first, then keep mechanical language subordinate to that origin.
- https://www.bilibili.com/opus/745737843276513317, "族吴苋与张芝的设计理念": source for clan design layers, hand-limit family language, sparse-record再创作, and the later shift toward lower reread cost. Key lesson: reduce dynamic text and deep self-looping unless the payoff is unmistakable.
- https://www.bilibili.com/opus/693405298689310759, "神孙权的设计历程与反思": source for design subjectivity, complexity cost, random skill pools, special-card burden, and wording normalization. Key lesson: borrowed mechanics can solve fit problems but consume player attention and reduce original design space.
- https://www.bilibili.com/opus/674737966604615718, "SP孟获的设计理念与隐喻": source for staged narrative, soft limits, mark removal tradeoffs, and global-listener loop cautions. Key lesson: removing marks may also remove memory, storage, and timing play; replace those functions with visible history or simpler windows.
- https://www.bilibili.com/opus/657130146618146848, "【绝征】三国杀diy教程：盘点新手在设计中的常见误区（by WAHX）": source for beginner-error guardrails. Key lesson: design for tabletop executability, keep text and effects compact, avoid excessive physical marks/cross-turn memory/unsafe insertion, give strong generals breakpoints, avoid passive blanks, specialize rather than become mediocre at everything, and use stable operation/timing wording.
- https://www.bilibili.com/opus/767005993036939264, "【杂谈】从零开始设计武将？你需要了解这些": source for from-scratch design flow. Key lesson: decompose skills into type, timing, condition, cost/action, effect, and aftereffect; map character anchors to attack/defense/burst/control/support/neutral/special roles before writing text; then refine timing, conditions, costs, and supplemental relations.
- https://www.bilibili.com/opus/771493374882480193, "【杂谈】警惕“华丽的陷阱”！来聊一聊技能联动那些事": source for internal skill-linkage taxonomy. Key lesson: linkage can be linear, insertion, split, support, implicit, mutually exclusive, or absent as compensation; linear/support/implicit links are usually cleaner, while forced linkage and insertion-heavy engines can become harder to play than they are worth.
- https://www.bilibili.com/opus/802610872555929635, "【杂谈】混沌与秩序！三国杀技能“时机”简述": source for timing-line design. Key lesson: place each trigger on a game, turn/phase, card-use, or damage line before polishing text; use before/when/after according to whether the skill replaces, interrupts, modifies, or summarizes an event, and avoid designs that depend on fragile same-timing ordering.
- https://www.bilibili.com/opus/815130006444310569, "【WAHX】三国杀新概念全点评·序": source for mechanism-quality evaluation, not a list of mechanisms to import. Key lesson: evaluate new concepts by innovation, generality, and robustness; distinguish small concept expansions from structural rule updates.

## Intake Rule For Future Sources

- User-confirmed workflow correction (2026-08-17): the design and evaluation process must preserve and reverse-check the rule-sensitive premises used during construction. Incorporated into `rules-priority.md`, `design-evaluation-framework.md`, and `SKILL.md`; it prevents a skill's operative text from relying on a rule interpretation contrary to the one used to justify its design.

When adding a new source, preserve only reusable design knowledge:

- design principle;
- mechanism definition and safe usage;
- package/mode scope if relevant;
- one short example or naming pattern;
- caution that prevents bad loops, excessive marks, or survival-card abuse.

If a source is mainly recap, rhetoric, or philosophy, absorb it only when it changes a decision rule, reference routing, naming method, or caution. Otherwise note in the final response that no skill update was needed.

When a source is absorbed, add one concise provenance entry here and merge the actual design guidance into the closest specialized reference file.

Workflow for user-supplied online sources:

- save fetched text or HTML in a workspace-local check folder, such as `.codex/source-check/`;
- summarize what was absorbed and where it was written;
- retain the fetched source in the ignored check folder for future rereading;
- validate the skill and make a local commit after absorption unless the user explicitly asks to review first;
- do not push to a remote unless the user explicitly requests it.

Do not store raw articles, full card tables, code paths, or code-level notes unless the user explicitly asks for a separate coding skill.
