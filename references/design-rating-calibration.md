# Relative Design Evaluation Anchors

Use this reference when comparing designs, applying absorbed contest results, or assigning scores. The canonical design process remains in `design-evaluation-framework.md`; this file defines how to describe relative evidence without turning one contest into an absolute scale.

## Relative Design Anchors

比较设计时，逐层使用同一组判断维度，再给整体结论。每层先记证据状态，不暗中折算成分数：

| 维度 | 较强证据 | 薄弱或缺失的证据 |
| --- | --- | --- |
| 规则与表达 | 操作均有合法、可追溯的路径，执行者、时机、成本和结束点明确。 | 关键条款依赖未写明的许可、相互矛盾的前提或未解决的分支。规则不成立属于门槛问题，不能靠其他项高分抵消。 |
| 人物契合 | 去掉技能名和设计说明，玩家实际做出的选择仍能表现具体人物锚点。 | 关联主要存在于名称或说明中，实际玩法却更像另一类人物。 |
| 主循环与选择 | 玩家有可重复且有意义的选择，至少在常见局面下优于普通替代行动。 | 理性路线是不开核心技能，或某一选项强到让表面上的选择失去意义。 |
| 反馈与强度 | 成本、收益和限制在最强重复路线下仍能推动预期玩法，并保留明确的失败点。 | 收益绕开预期行动、成本反转资源方向，或名义限制无法控制产出。 |
| 技能结构与互动 | 每项技能各有工作，联动提供支持而不强迫执行；其他角色仍有实际选择或反制空间。 | 技能只充当燃料、联动让技能组变脆，或把广泛影响误当作互动。 |
| 桌面执行 | 状态、历史、选择和清理方式可见且易于核验。 | 隐藏或长期记忆、检索、嵌套结算或反复改写状态，使玩家难以确认当前局面。 |
| 新意（仅在命题要求时） | 机制带来有意义的新选择或人物解释，同时保持清晰和契合。 | 只给熟悉模板换名，或新机制增加复杂度却没有改变有效玩法。 |

每层标为**突出、成立、有条件、证据不足**：突出需要反复或直接证据；成立表示常见边界下运作可靠；有条件表示依赖项或具体风险尚存；证据不足表示现有文本、玩法或来源材料不能支持判断。逐层给出标签、证据和首要问题，再提出最小修法；不把画像合成单一总分，也不平均掉规则硬伤。仅在用户或赛事要求时打数值分。
