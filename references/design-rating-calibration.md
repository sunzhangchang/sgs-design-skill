# Relative Design Evaluation Anchors

Use this reference when comparing designs, applying absorbed contest results, or assigning scores. The canonical design process remains in `design-evaluation-framework.md`; this file defines how to describe relative evidence without turning one contest into an absolute scale.

## Relative Design Anchors

评审时按下表主动找反例，再记录各层状态。表中的信号是测试入口，不是自动判错；必须给出具体文本或局面、实际行为和后果。

| 维度 | 成立信号 | 常见缺点信号与影响 |
| --- | --- | --- |
| 规则与表达 | 对象、权限、时机、顺序和结束点能逐步结算。 | 缺权限、对象或后续条件时，尝试按字面执行；若走不通或产生多种结果，这是规则问题，不是低分项。 |
| 人物契合 | 去掉名称和说明，玩家动作仍表现具体人物事实。 | 只靠典故或技能名解释；去名后玩法指向别的人物或泛用模板。 |
| 主循环与选择 | 玩家愿意在有代表性的局面启动技能，且有真实取舍。 | 与不发动、直接摸牌或普通用牌相比没有收益；或一条选项明显支配其他选择，使技能变成伪选择。 |
| 反馈与强度 | 成本和收益推动预期行动，限制能约束最强重复路线。 | 奖励可绕过主动作、代价反而喂大收益、限制能被轻易规避，常导致不发动或重复爆发。 |
| 结构与互动 | 每项技能能独立完成一项工作，联动和对手回应都有意义。 | 一技只为另一技供料、拆开就无法运行、队友收益自动化或敌方无普通突破口，导致技能组僵硬或缺乏对抗。 |
| 桌面执行 | 状态、历史、选择和清理点可见、可复核。 | 依赖隐藏记忆、跨回合追牌、复杂检索或嵌套时序且没有简明记录，面杀容易漏结算或无法复盘。 |
| 新意（命题要求时） | 新机制改变了有价值的玩家决策，并保留清晰度与人物契合。 | 只换名不改行为，或增加术语和操作却没有新增有效选择，复杂度没有回报。 |

先检查用户命题与规则合法性，再分层标为**突出、成立、有条件、证据不足**。报告缺点时按“触发场景 → 实际行为 → 后果 → 首个失效层 → 最小修法”组织；区分硬性阻断、核心缺陷、条件性风险和表达润色。只有偏好而无可复现场景时，标为偏好；尚未推演的可能性标为待验证，不写成已证实缺点。除非用户要求，不合成单一总分，也不平均掉规则硬伤。
